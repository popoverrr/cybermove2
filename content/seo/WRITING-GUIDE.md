# Как писать разборы Cyber Move Consulting (SEO-статьи)

Рабочее руководство для авторов 88 новых статей (docs/16-seo.md). Читать целиком перед первой статьёй.

## 0. Главное

- Статья должна быть **полезнее топ-5 выдачи** по своему главному запросу. Перед написанием посмотрите выдачу (WebSearch), поймите, что там уже есть и чего не хватает. Ваше преимущество — конкретика для Казахстана, порядок действий, таблица или расчёт, которые читатель может повторить, и честность («зависит от…» с объяснением факторов вместо выдуманной цифры).
- **Ничего не выдумывать.** Нет клиентов, результатов, цифр, цитат, отзывов, исследований, статистики, имён авторов без источника. Пример с числами допустим, только если он явно назван условным («условный пример», «округлённые числа для иллюстрации»).
- **Факты о законах, госзакупках, налогах, тарифах, ценах, функциях платформ** (Kaspi, WhatsApp Business, Meta, Google Ads, TikTok, Яндекс, 2GIS, egov, goszakup) — только после проверки по первоисточнику (WebSearch + WebFetch): adilet.zan.kz, goszakup.gov.kz, egov.kz, kgd.gov.kz, справка платформы. Источник — ссылкой в тексте и в `sources`. Учитывайте дату: в Казахстане с 1 января 2025 года действует новый Закон «О государственных закупках» (от 1 июля 2024 года № 106-VIII) — проверяйте действующую редакцию. Проверенные факты по госзакупкам (из пилотной статьи `src/content/insights/ru/tenders-legal/goszakup-registration.md` — прочитайте её источники): goszakup.gov.kz сейчас перенаправляет (301) на zakup.gov.kz («Единая платформа закупок»); действуют Приказы Минфина РК № 627 от 16.09.2024 (Правила использования единой платформы закупок), № 646 от 26.09.2024 (реестры), № 687 от 09.10.2024 (Правила осуществления госзакупок); adilet.zan.kz без JS отдаёт пустую страницу — тексты можно сверять по официальным зеркалам, но в `sources` ставить ссылку adilet. Не нашли первоисточник — не пишите конкретику (номера статей, суммы, сроки), дайте общий порядок и рекомендацию сверить у юриста, поставьте `legalCheck: true`.
- Качество важнее объёма: если тема не тянет на сильный текст — напишите в отчёте агента, а не добивайте водой.

## 1. Файл

`src/content/insights/ru/<rubric>/<slug>.md` — рубрика и слаг из `content/seo/articles-plan.tsv`.

```yaml
---
title: "…"                  # H1, можно улучшить рабочий заголовок из плана
seoTitle: "…"               # <title>, ≤ 60 знаков, главный запрос ближе к началу, без капслока и «!», без названия компании
description: "…"            # 140–160 знаков (считать!), польза статьи, главный запрос, без «лучший/№1»
rubric: audit               # = папка
publishDate: 2026-10-08     # дата волны из content/seo/waves.json (волна — столбец wave плана)
updatedDate: 2026-10-08     # = publishDate
author: editorial
primaryKeyword: "…"         # из плана (столбец primary_keyword)
keywords: ["…", "…"]        # главный + дополнительные из плана + 1–3 близких
serviceLink: /services/…/   # из плана (столбец service_link), как есть
related: [slug, slug, slug] # 3 близкие статьи из плана или из 12 прежних
cases: []                   # слаги реальных кейсов /cases/<slug>/, только если действительно по теме (обычно 0–2)
summary:                    # «Коротко»: 3–5 пунктов, каждый — законченная мысль ≤ 20 слов
  - "…"
cover:
  motif: checklist          # из плана (столбец cover_motif)
  alt: "…"                  # что изображено, по-русски, 8–20 слов
  data: { … }               # содержимое обложки из текста статьи, см. §4
readingMinutes: 8           # ≈ слова / 180
faq:                        # 0–5, только вопросы, которые реально задают (по выдаче «Похожие вопросы»), ответ 2–4 предложения
  - q: "…"
    a: "…"
sources:                    # все первоисточники фактов
  - title: "…"
    url: "https://…"
legalCheck: false           # true — если конкретику не удалось проверить по первоисточнику
draft: false
---
```

YAML: строки в двойных кавычках; внутри — «ёлочки», не прямые кавычки.

## 2. Структура текста (тело после frontmatter)

H1 не пишется в теле — он из `title`. Тело начинается с абзаца.

1. **Прямой ответ** — первый абзац, 2–3 предложения, содержит главный запрос и отвечает на него по существу (это кандидат в «featured snippet»). Если запрос — термин, первое предложение — определение: «Платформа бренда — это …».
2. По желанию — одно предложение о том, кому и для какой задачи статья. Не начинать с «Ниже —», «В этой статье», «Разберём», «Дальше —»: оглавление сайт строит сам, анонс разделов не нужен.
3. Разделы `##` (5–9 штук) и `###` внутри. Главный запрос (или его естественная форма) — хотя бы в одном `##`. Оглавление и «Коротко» сайт строит сам из `##` и `summary`.
4. **Практическая часть** — обязательно: чек-лист, шаблон, расчёт на примере, таблица сравнения. Таблицы — markdown (`| … |`), списки — markdown.
5. `## Типичные ошибки` — 4–7 пунктов.
6. `## С чего начать` — 3–5 шагов на ближайшую неделю.
7. Последний абзац — **CTA** одним абзацем, без давления: естественная ссылка на страницу услуги (`serviceLink`). Формулировка своя в каждой статье; не начинать с «Если…» по шаблону. Ссылка на услугу должна быть и раньше в тексте, по смыслу.
8. FAQ и источники пишутся во frontmatter — в теле их не повторять.

Объём 1 400–2 500 слов (без учёта блоков figure): столько, сколько нужно, чтобы закрыть вопрос полностью.

## 3. Тон и язык

- Спокойно, конкретно, уверенно. Абзац ≤ 4 предложений. Предложения короткие. Русский — естественный деловой, не калька с английского.
- Запрещено (проверяется скриптом): «в современном мире», «не секрет, что», «давайте разберёмся», «ни для кого не секрет», «в наше время», «играет важную роль», «является неотъемлемой частью», «подводя итог», «в данной статье», «в этой статье мы», «как известно», «на сегодняшний день», «лучший», «№1». Также избегать: «уникальный», «революционный», «эффективный инструмент», «в рамках данного», «осуществлять», риторических вопросов подряд, восклицательных знаков, эмодзи.
- Каждая статья начинается по-своему. Не используйте одинаковые вводные, переходы и концовки в разных статьях — скрипт ловит совпадения фраз (шинглы по 5 слов, порог 15 % на пару) и одинаковые абзацы.
- Местная специфика там, где она есть: Kaspi (Kaspi.kz, Kaspi Pay, Kaspi Магазин), 2GIS, goszakup.gov.kz, egov.kz, налоговые режимы РК, тенге (₸), Алматы/Астана/Шымкент, два языка (ru/kk), WhatsApp как главный канал общения с клиентами.
- Подход компании, где уместно: CHAOS → CORE → SYSTEM → GROWTH (сначала диагностика и ядро — продукт, аудитория, позиционирование, ценность, оффер; потом система — каналы, продажи, CRM, автоматизация; потом рост). «AI должен работать, а не впечатлять»: автоматизировать процесс, который уже работает.
- Образец тона — `src/content/insights/ru/systems/choose-crm-kazakhstan.md`, `src/content/insights/ru/audit/unit-economics-cac-ltv-romi.md`.

## 4. Обложка (`cover.data`) и иллюстрации в тексте

Обложку и схемы рисует генератор `scripts/lib/figures.mjs` из данных, которые вы задаёте. Данные — **из текста статьи** (этапы, пункты, варианты, значения из вашего примера). Подписи короткие: 1–4 слова (в flow/document/checklist — до 6).

| motif | data |
|---|---|
| `funnel` | `{ stages: [{ label, value? }] }` — 3–6 этапов; `value` только если в статье есть пример с этими числами |
| `chart` | `{ type: "bar" \| "line", x: [подписи], series: [{ name, values: [числа] }], unit?: "₸", highlight?: индекс, xLabel? }` — 1–3 серии, числа из расчёта в статье |
| `matrix` | 2×2: `{ kind: "2x2", xAxis, yAxis, cells: [{ title, note? }] ×4, accent? }`; таблица: `{ kind: "table", columns: [..3–4], rows: [[..], ..] ≤ 6, accent?: № столбца }`, ячейки «+»/«−» рисуются галочкой/чертой |
| `flow` | `{ steps: ["…", …] }` — 3–10 шагов, `accent?` |
| `timeline` | `{ unit: "Недели", unitShort: "W", total: 8, items: [{ label, span: [первая, последняя], note? }] ≤ 8 }` — номера единиц с 1 включительно: `[2, 3]` = недели 2–3 |
| `checklist` | `{ items: ["…"] 5–7, checked?: число отмеченных }` |
| `document` | `{ kicker: "Договор", title: "…", sections: ["…"] 5–8, accent? }` |
| `network` | `{ center: "CRM", nodes: ["…"] 4–9, edges?: [[i, j]] }` |
| `grid` | `{ frames: [{ label, ratio: "9:16" \| "1:1" \| "4:5" \| "16:9", note? }] 2–5 }` |
| `map` | `{ points: [{ city, note? }] }` — города: Алматы, Астана, Шымкент, Караганда, Актобе, Тараз, Павлодар, Усть-Каменогорск, Семей, Атырау, Костанай, Кызылорда, Уральск, Петропавловск, Актау, Туркестан, Талдыкорган, Кокшетау, Экибастуз, Жезказган |
| `dashboard` | `{ kpis: [{ label, value?, trend?: "up" \| "down" }] 4–8 }` |

`accent` — индекс выделенного элемента (зелёный акцент), выберите самый важный по смыслу статьи.

**Иллюстрации внутри статьи: 1–2 на статью**, в месте, где они поясняют текст. Блок кода с языком `figure` и JSON (строго валидный JSON, двойные кавычки):

````md
```figure
{"motif": "flow", "caption": "Рис. 1. Порядок внедрения CRM", "data": {"steps": ["Цели", "Процесс", "Выбор", "Настройка", "Обучение"]}}
```
````

Можно задать `"ratio": 0.5` (высота/ширина, по умолчанию 0.62) для широких схем. Иллюстрация не повторяет обложку один в один — покажите другой аспект (например, обложка — чек-лист, внутри — таблица сравнения или схема процесса). Мотивы внутри — любые из таблицы.

## 6. Проверка своей статьи

1. `node scripts/seo-check.mjs` — исправить все ❌ своей статьи (ошибку «cover files not rendered» игнорировать — обложки рендерит координатор). `npm run seo:check -- --warn` показывает и замечания ⚠.
2. Посчитать длины `seoTitle` (≤ 60) и `description` (140–160).
3. Перечитать как редактор: нет ли воды, повторов, штампов, кальки; каждое утверждение с цифрой — с источником или пометкой «условный пример».
4. **Не запускать** `npm run covers`, `node scripts/article-covers.mjs` и `npm run build` — параллельно работают другие авторы, общий кеш обложек ломается; обложки рендерит координатор. Не трогать чужие статьи и код сайта.
